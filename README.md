# IR-Sauron
<img width="543" height="544" alt="image" src="https://github.com/user-attachments/assets/303726ef-2fab-4bac-89e9-656fac24bf8d" />


Конструктор тайлайна расследований инцидентов информационной безопасности (Incident Response Timeline).

Приложение помогает IR-команде вести инциденты: принимать алерты в очередь триажа, эскалировать их в инциденты (по одному или сразу пачкой), реконструировать граф связей между событиями атаки, размечать факты по MITRE ATT&CK, прикреплять артефакты и IOC, обсуждать события в комментариях и выгружать инцидент в JSON для отчётности.

## Возможности

- **Алерты**: очередь триажа с фильтрами (статус, критичность), поиском по дате/статусу/описанию и постраничной навигацией (50/100/200/500 на странице); эскалация в инцидент (одиночная и массовая), привязка/отсоединение алертов от инцидента, назначение ответственного («Назначено», быстрое «Взять себе»), тэги (вручную или по правилу), мягкое удаление с архивом и восстановлением. Карточка алерта показывает разобранные URL/IP-адреса/учётные записи/файлы (из структуры ECS для Elastic-источников или эвристически из текста), исходный индекс Elasticsearch и панель «Похожие алерты» — другие алерты с тем же внутренним IP или учётной записью.
- **Правила алертов**: автоматическое подавление шума, эскалация или назначение тэга новым алертам по условиям (источник, критичность, подстрока в заголовке/описании) — как для вручную созданных алертов, так и для подтянутых по расписанию из внешних источников; создание правила из выделенных алертов с живой проверкой числа совпадающих алертов до сохранения.
- **Источники алертов** (панель администрирования): подключение Elastic, TheHive, чтение из файла (CSV/JSON по сетевой папке и маске имени), почтового ящика по IMAP и произвольного JSON REST API по API-ключу — автоматический периодический опрос и синхронизация по кнопке, с шифрованием учётных данных в базе; таблица источников на всю ширину экрана.
- **Статистика**: сводка по алертам за выбираемый период (24 часа по умолчанию, текущая неделя, 7 дней, текущий месяц, 30 дней, произвольный «Период») — график количества по времени, разбивка по статусам и типам угроз, топ URL, IP-адресов и учётных записей, встречающихся в алертах; отдельный блок статистики по учётным записям системы.
- **Анализ**: граф связей между алертами по общим внутренним IP-адресам, учётным записям, файловым операциям и структурированным IOC (домены/URL/хеши/email) — строится по поисковому запросу (в том числе по имени алерта или инцидента), а не автоматически при открытии раздела, с фильтрацией категорий узлов и жирной обводкой эскалированных алертов; узлы можно перетаскивать мышью со стягиванием связей, кнопка «Автораскладка» пересчитывает физическую раскладку заново; кнопка «В анализ» на карточке алерта, в списке алертов инцидента и в IOC инцидента сразу открывает раздел с готовым запросом по выбранному значению.
- **Инциденты**: единый статус (открыто/в работе/подтверждён/отклонён), критичность, гриф конфиденциальности; поиск по номеру, названию, IOC, IP-адресам, учётным записям и файлам; постраничная навигация с настраиваемым размером страницы; вкладка «Отчёт» в две колонки — авто-заполняемые блоки (сводка, хронология событий, сопоставление с MITRE ATT&CK, таблицы IOC и приложений-доказательств) рядом с редактируемыми разделами (ключевые метрики MTTD/MTTR, анализ атаки, затронутые активы, оценка ущерба, реагирование и меры, выводы и рекомендации, свободный текст отчёта) и выгрузкой в PDF; экспорт в JSON.
- **Таймлайн**: список фактов инцидента с типом, достоверностью и MITRE-разметкой.
- **Граф**: конструктор графа связей между событиями — узлы-факты (сетевое соединение, событие логона, операция с файлами, выполнение команды) с масштабированием и панорамированием; форма создания связи объединяет тип связи, дату/время перехода и технику MITRE; расположение узлов сохраняется между визитами, а новые узлы автоматически выстраиваются в колонки по причинно-следственной глубине связей вместо хаотичной сетки.
- **IOC и артефакты**: индикаторы компрометации, загрузка файлов-доказательств с WORM-защитой.
- **Комментарии**: обсуждение фактов внутри инцидента.
- **Панель администрирования**: пользователи (деактивация и активация, таблица на всю ширину экрана), настраиваемая матрица прав по ролям, источники алертов, уведомления на почту и в Telegram-бота, часовой пояс (с разницей в часах в выпадающем списке), зашифрованные паролем бэкапы и восстановление конфигурации и базы данных — с индикатором прогресса и страницей техобслуживания на время восстановления, и лог действий — изменения настроек панели администрирования и факты удаления инцидентов/алертов с фильтром по типу объекта и действию.
- **Роли и RBAC**: администратор, руководитель IR, аналитик, наблюдатель, внешний подрядчик — права на конкретные действия настраиваются в панели администрирования.
- **Темы оформления**: светлая, тёмная, «Саурон» и «Трандуил» (пасхалки) — в теме «Саурон» статус инцидента в списке и карточке отображается иконкой Ока, в теме «Трандуил» — иконкой листа; у каждой темы своя надпись-водяной знак в верхнем меню и свой favicon.
- **Справка**: страница с описанием разделов и возможностей приложения, доступна всем пользователям из верхнего меню.

## Стек технологий

- **Backend**: FastAPI (Python), SQLAlchemy (async), PostgreSQL, Redis, MinIO (S3-совместимое хранилище артефактов), WebSocket для совместной работы в реальном времени.
- **Frontend**: React + TypeScript, Vite, Zustand.
- **Инфраструктура**: Docker Compose, Nginx, опционально Keycloak/OIDC для SSO.

## Быстрый старт

```bash
cp .env.example .env
make dev     # dev-стек с hot-reload
# либо
make up      # production-стек
```

Frontend будет доступен на `http://localhost:3000` (dev) или через Nginx на `http://localhost` (production).

## Требования к установке

- **Docker** 24+ и **Docker Compose** v2 (команда `docker compose`, а не устаревший отдельный `docker-compose`).
- Linux-хост (проверено на Debian/Ubuntu) или Docker Desktop (Windows/macOS) для локальной разработки.
- Свободные порты **80** и **443** на хосте (Nginx) — либо переназначьте их в `docker-compose.yml`.
- Ориентировочно не менее **2 vCPU** и **4 ГБ RAM**, **10 ГБ** свободного места на диске — для тестового стенда с небольшим объёмом данных; под боевую нагрузку ресурсы стоит считать исходя из реального объёма алертов и дел.
- TLS-сертификат в `nginx/ssl/cert.pem` и `nginx/ssl/key.pem` — по умолчанию самоподписанный для разработки, для продакшена замените на сертификат от доверенного CA.
- Заполненный `.env` (скопируйте из `.env.example`): как минимум пароли PostgreSQL/Redis/MinIO и `SECRET_KEY` для подписи JWT.
- Клиент `pg_dump`/`pg_restore` внутри backend-образа зафиксирован на версии **PostgreSQL 16** (через репозиторий PGDG) — под версию сервера `postgres:16-alpine` из docker-compose. При восстановлении бэкапа базы данными снаружи контейнера используйте клиент той же версии, иначе `pg_restore` может завершиться с ошибкой несовместимости.
